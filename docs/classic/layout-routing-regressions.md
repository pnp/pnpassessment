# PublishingLayoutPage admission regression coverage

## Scope

Version 1 admission uses `PublishingLayoutTypeEvidence.IsConfirmedMember`, not ContentType or a sticky purpose flag. The scan version is read from storage by discovery, the discovery writer and page routing, including after restart. Source inspection precedes list-item admission, including root/catalog files without list items. Merges combine source observations before deriving purpose and suppressing a confirmed member's `PublishingPage` projection. A derived `ExcludedAsset` disposition without current proof returns to pending routing; retained Denied/Failed/Unknown evidence is not cleared.

There are no schema changes, migration edits, report filters, historical data repairs, new scanners or CLI changes in this routing revision. The dependency remains unchanged. Layout-reference resolution is a separate consumer and is not changed here; the existing reference assertions remain useful but do not establish acceptance of a revised target-evidence rule.

## Superseded expectations and their replacements

- **AspxAssetPurposeTests**: `Layout_content_type_not_location_proves_an_asset` is replaced by `Own_type_not_content_type_or_location_proves_an_asset`. The same catalog/outside-catalog, descendant and case variants now first assert Unknown from metadata alone, then require own-file source evidence for confirmation. Publishing metadata still retains PublishingPage classification, but confirmed content purpose also requires proven non-membership. Catalog uncertainty keeps its original metadata reason along with the explicit type-purpose uncertainty reason rather than asserting a single metadata-only reason.
- **Purpose persistence/casing/sparse-update tests**: retain the existing identity, database/native CSV, case-insensitive metadata comparison and Denied/Failed/Unknown checks. Layout fixtures now carry source proof and version 1 authority. `ConfirmedPublishingLayoutFamily` replaces the superseded `PageLayoutContentType` reason. The retained ContentType and source observation JSON are asserted independently instead of treating accumulated ContentType purpose reasons as type proof. Repeated stale PublishingPage projections cannot reintroduce that classification. Additional tests inject stale PageLayout/ContentPage confirmation and derived exclusion to ensure it cannot override Unknown or NonMember evidence.
- **AssessmentPageMetadataReplayTests**: the production admission regression still checks the same physical inventory, eligible Publishing/raw pages, enrichment inputs, remediation codes, publishing summary and native reports. The catalog and outside assets now have source evidence. The outside asset's expected metadata request count changes from one to zero: source confirmation must prevent the request, not let ContentType from that request establish exclusion. The no-list/no-selection failure cases now exclude a confirmed root without any ContentType, while preserving their failure details. Unrelated computed-field, identity, optional-field, home-page and page-type tests are retained.
- **AssessmentLayoutAccountingReplayTests**: all seven reference/failure scenarios remain. The successful scenario additionally runs with root, direct and indirect subclass evidence from the production metadata reader. The catalog file has no list item; the outside file has Publishing ContentType, not Page Layout ContentType. Neither reaches extraction, storage, remediation or rollups. The real Publishing envelope declares TemplateRedirectionPage and includes a separate-handler delegation in its synthetic source. Its own declaration/evidence, physical identity, Layout name, known URL and analysis survive. Type evidence is checked in both discovery storage and native CSV. These synthetic declarations are not runtime-handler observations.
- **SharePointLiveAspxDiscoveryRegressionTests**: no expectations removed. Added actual provider-to-discovery-to-routing root-file cases (root/direct/indirect, no list item and no ContentType), plus repeated Publishing metadata projection merges for members, non-members and unavailable source. Existence is checked in storage before the source read.
- **PublishingLayoutTypePersistenceTests**: the existing source-acquisition and repeated-observation tests now record version 1 authority, retaining every original field/CSV/failure/coverage check. Added Unknown purpose assertions for missing/denied/failed source and conflicts. Conflicting evidence cannot leave an earlier derived exclusion in force. Coverage failures still have unknown counts, never successful empty counts.
- **PublishingLayoutTypeUpgradeTests**: retains additive-upgrade assertions and the actual StorageManager new-scan/consolidation/restart path. Adds routing under the reloaded version and preservation of stored historical Publishing classification, purpose, failure, Layout/URL and analysis through restart and finalization. Existing ClassicLayoutUpgradeTests still compare every historical column and native reports after upgrade.
- **AssessmentTypeRoutingReplayTests**: new complementary tests cover direct metadata-load exclusion, misleading Page Layout ContentType/descendants with proven non-members or unknown ancestry, and Publishing metadata with unavailable/unresolved source. Existing eligible Wiki/Publishing behavior remains, without promoting unknown purpose to confirmed content purpose.

No existing test is deleted, skipped or disabled. Legacy purpose/reference fixtures that remain version 0 intentionally test the preserved historical behavior, not corrected admission.
